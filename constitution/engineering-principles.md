# Engineering Principles

1. **Understand before implementation.** Coding is downstream of understanding.
2. **Evidence beats assumption.** Prefer observed runtime behavior, executable repository evidence, tests, and approved specifications over model assumptions.
3. **Human authority is explicit.** The human owns product intent, scope, business rules, architecture decisions, constraints, and release approval.
4. **Scope is bounded.** Change only what the task requires.
5. **Existing patterns are the default.** Introduce new abstractions only when existing ones cannot safely satisfy the requirement.
6. **Verification is part of implementation.** A change is not done because code was written.
7. **Security is a design concern.** Security review is required when a change affects trust boundaries, authorization, data exposure, secrets, or abuse surfaces.
8. **Git is traceability.** Commits should map to coherent engineering objectives.
9. **Uncertainty must be visible.** Report assumptions, unknowns, and verification gaps rather than hiding them.
10. **Stop at the acceptance boundary.** Do not turn a bounded task into an unsolicited cleanup project.
