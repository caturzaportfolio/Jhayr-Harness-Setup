# Planning Workflow

Use planning when a change is meaningful, cross-cutting, risky, or involves multiple implementation steps.

1. State the objective.
2. Define the exact scope.
3. Map the affected layers and existing patterns.
4. Identify data/API/frontend/security/testing/deployment implications as applicable.
5. Break the work into small, reversible steps.
6. Define verification for each meaningful step.
7. Identify explicit stop conditions and unresolved decisions.

Prefer vertical slices that can be independently implemented and verified.
